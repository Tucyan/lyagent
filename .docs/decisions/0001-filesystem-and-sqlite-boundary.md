# ADR-0001：文件保存业务内容，SQLite保存任务控制状态

- 状态：Accepted
- 日期：2026-08-02

## 背景

系统运行在个人Windows主机，主要处理Markdown、图片、评分表和批改结果。课程知识结构需要能够直接浏览、备份和版本化；批量批改则需要并发领取、租约、重试和崩溃恢复。

把全部内容拆入关系数据库会增加Schema和迁移成本；只使用文件又难以可靠实现并发状态转换。MVP明确不引入Redis、分布式Worker或向量数据库。

## 决策

- Markdown、图片、不可变知识release、冻结Rubric、正式批改结果和审计事件保存在Workspace文件中。
- SQLite只保存批次、job、问题、租约、状态、计数缓存、路径和哈希等控制数据。
- 正式单份批改JSON是成绩结果的事实来源；Markdown和CSV是可重建派生物。
- 跨文件与SQLite不假装使用单一事务，采用“原子文件发布、结果哈希、SQLite终态提交、启动协调”的协议。
- 知识库使用staging、不可变release和`active.json`指针发布，答疑只读取active release。

## 影响

优点：

- 课程资料和结果可直接检查、备份和导出；
- SQLite Schema保持在任务控制范围内；
- 不依赖额外服务即可支持个人主机运行；
- CSV、索引和计数可以确定性重建。

代价：

- 文件与SQLite之间需要显式协调和故障注入测试；
- 文件发布必须使用临时文件、原子rename和哈希；
- 不能通过手工编辑数据库或正式结果文件处理运行故障；
- 大规模、多主机或多租户场景可能需要重新设计。

## 重新评估条件

满足任一条件时重新评估，但不直接修改本ADR：

- 需要多个进程或多台主机同时写入同一Workspace；
- 单机批次数量或数据规模使启动协调无法在可接受时间完成；
- 需要跨课程复杂查询、事务化统计或多租户隔离；
- 文件系统不再提供可靠的同卷原子rename；
- 业务要求由外部系统成为正式成绩的事实来源。
