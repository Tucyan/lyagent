# 运行与安全

## 运行边界

本项目面向个人Windows主机。M1/M2提供仅监听`127.0.0.1`的Fastify API、资料管理端和`/qa`课程答疑页；SQLite队列和企业微信仍属于待实现能力。

未来管理API默认只监听`127.0.0.1`。若需要局域网或公网访问，必须先增加身份验证、TLS、CSRF防护、速率限制并记录ADR，不能只修改监听地址。

## 文件安全

所有业务文件操作必须经过受控Workspace和Service：

- 拒绝绝对、UNC、设备和NTFS ADS路径；
- 规范化Windows大小写；
- 逐段检查并拒绝symlink、junction和其他reparse point；
- 校验真实父目录仍位于授权根目录；
- 限制扩展名、单文件大小、目录深度、文件数和导入总大小；
- Agent只看到逻辑相对路径，不获得绝对路径。

当前`Workspace`只防护普通绝对路径和`..`，在安全加固完成前不得把资料导入接口暴露给不可信用户。

## 密钥和敏感数据

- 当前 DeepSeek 模型密钥只从被忽略的`workspace/config/app.json`读取；DDGS 搜索不需要 API key；未来 WeCom Secret、Token 和 EncodingAESKey使用本地凭据存储。
- 示例配置只包含非敏感默认值和占位字段名，不包含可用凭据。
- 学生作业、课程资料、会话和批改结果属于敏感业务数据。
- API错误、普通日志和审计索引不得包含完整正文。
- 调试时如需内容片段，使用合成或脱敏数据并限制长度。

## 日志与审计

普通运行日志记录：

- 请求、session、batch和job的内部ID；
- 状态转换、耗时、重试次数和错误类型；
- release、Rubric、Prompt、提交和结果哈希；
- Provider请求ID（若可获得）。

普通日志不记录Prompt全文、学生正文、密钥、回调明文或完整模型响应。教师修改使用独立追加写审计事件，保存修改人、时间、前后哈希、结构化Patch和备注。

M2 的 SSE 响应同样视为安全边界：只发送回答文本、经验证引用与受限工具步骤，不能发送思维链、完整工具参数、资料原文、绝对路径或模型密钥。

## 公开网页读取

- 网络搜索默认走本机 DDGS helper，外部网页只能通过本会话的搜索结果 ID 读取，不能由模型提供任意 URL。
- 读取仅允许 HTTPS；解析域名和每次重定向都会拒绝环回、私网、链路本地和云元数据地址。
- 仅处理 HTML/纯文本，设置请求超时与响应上限；网页内容是不可信参考资料，不执行其中指令，也不写入普通日志或会话文件。

## 启动恢复

应用启动顺序：

1. 加载并校验非敏感配置；
2. 检查Workspace目录权限和路径边界；
3. 打开SQLite，启用外键并执行版本化迁移；
4. 校验active knowledge指针；
5. 协调正式结果文件与job状态；
6. 清理无引用临时文件；
7. 恢复未过期租约并重新排队可重试job；
8. 最后启动API、Channel和队列消费者。

恢复逻辑必须幂等，连续启动两次不能改变已经协调完成的状态。

## 备份与回滚

一致性备份至少包含：

- `workspace/knowledge/`；
- `workspace/assignments/`；
- `workspace/state/app.db`；
- 需要保留的非敏感配置。

备份前暂停领取新job并等待当前原子发布结束。知识库回滚通过切换`active.json`完成；批改结果不原地覆盖，教师修订通过审计事件和新结果哈希表达。

在实现自动删除前，正式结果和审计默认保留。任何批量删除功能必须先展示确定目标、要求确认，并使用可恢复方式或经过验证的备份。

## 企业微信

正式接入前必须完成目标组织内的连接验证，明确回调或长连接方式以及本机网络前提。适配器必须实现：

- 验签、解密和时间窗口检查；
- 消息幂等与短期去重；
- 快速确认和异步处理；
- 有上限的限流、超时和5xx重试；
- 用户、群和课程映射校验；
- 长消息安全拆分；
- 日志脱敏。

重复投递不得产生第二次Agent调用。未知用户、群或课程映射必须在调用模型前拒绝。

## 故障排查

| 现象 | 首先检查 |
|---|---|
|启动失败|Node ABI、配置Schema、Workspace权限、SQLite迁移|
|课程仍显示旧内容|`active.json`、release manifest和发布日志|
|job长期running|租约、worker日志、正式结果文件及resultHash|
|CSV缺行|终态JSON数量；重新运行单写者聚合，不手改CSV|
|重复批改|幂等键、唯一约束、启动协调顺序|
|企业微信重复回复|消息ID、去重保留期和异步重试记录|

故障处理不得直接修改SQLite状态或正式JSON。需要人工修复时先备份、记录原因，并通过受控维护命令执行。
