# 运行与安全

## 运行边界

本项目面向个人Windows主机。M1/M2提供仅监听`127.0.0.1`的Fastify API、资料管理端和`/qa`课程答疑页；SQLite队列和企业微信仍属于待实现能力。

所有`/api/`请求还会校验`Host`仅为`127.0.0.1`、`localhost`或`[::1]`。带有`Origin`时要求其为HTTP环回来源；正式运行配置了允许来源后，还必须与该精确来源一致。开发Vite代理会把`Origin`改写为API来源，发布页面与API使用同一来源。缺少`Origin`的本地非浏览器请求仍可用。该限制覆盖健康、课程和批改API，用于阻止DNS rebinding把攻击者域名解析到本机后读取未鉴权数据。模型设置写接口仍额外要求实际环回连接、精确配置的`Origin`和CSRF Token。

未来管理API默认只监听`127.0.0.1`。若需要局域网或公网访问，必须先增加身份验证、TLS、CSRF防护、速率限制并记录ADR，不能只修改监听地址。

## 文件安全

所有业务文件操作必须经过受控Workspace和Service：

- 拒绝绝对、UNC、设备和NTFS ADS路径；
- 规范化Windows大小写；
- 逐段使用`lstat`拒绝被Node识别为symlink的路径组件，并检查现有组件的`realpath`仍位于本次调用解析出的Workspace物理根内；真实路径越界时拒绝访问；
- 读取文件时打开句柄、检查其为普通文件并从同一句柄读取，避免打开后仅替换路径就改变读取对象；
- 限制扩展名、单文件大小、目录深度、文件数和导入总大小；
- Agent只看到逻辑相对路径，不获得绝对路径。

这些检查能防止路径穿越和检查时已存在、且解析到Workspace根外的路径重定向，不构成对并发本地文件系统攻击者的完整防护。纯Node路径式文件API无法把逐段检查与后续打开、写入、rename或删除原子绑定；Node在Windows上也不提供本项目所需的目录句柄相对操作。运行前提是Workspace及其祖先目录不会被不可信本地进程并发改写；有权并发改写这些目录的同用户进程仍可能在检查与使用之间替换路径。读取句柄只固定成功打开的文件对象，不保证打开瞬间的父目录解析安全。若威胁模型要求抵御该类本地攻击，需要native handle-relative文件系统helper或隔离进程/账户与ACL方案，并重新评估所有路径型修改操作。

当前`Workspace`自身只防护普通绝对路径和`..`，不得单独作为受控文件访问边界。

## 密钥和敏感数据

- 模型密钥按Provider ID经Windows当前用户DPAPI保护，保存在Workspace外的`%LOCALAPPDATA%\CourseAgent\secrets\<workspace-sha256>`；哈希来自`realpath`规范化（Windows忽略大小写）后的Workspace绝对路径，不同Workspace不得共享凭据目录。普通JSON、日志、命令行和API响应不得包含密钥。旧`workspace/config/app.json`中的`deepseekApiKey`只读兼容，模型设置验证及凭据保存成功后原子改写非敏感配置并移除明文。DDGS搜索不需要API key；未来WeCom Secret、Token和EncodingAESKey使用同类本地凭据存储。
- 示例配置只包含非敏感默认值和占位字段名，不包含可用凭据。
- 学生作业、课程资料、会话和批改结果属于敏感业务数据。
- 批量上传原件和附件只进入 Workspace 内受控 `batch-uploads/` staging；草稿取消只清理尚未产生会话的数据，已创建会话默认保留。附件路径必须位于 `assets/`，并通过路径、扩展名和文件魔数校验。
- active knowledge release 是批改的可选增强项；缺失时知识工具返回 `ACTIVE_RELEASE_NOT_FOUND`，不得在模型调用前中止批改。运行失败只保存安全错误码和教师可操作提示，不保存供应商原始响应、Prompt、密钥或完整学生正文。
- M4上传先写入受控临时文件，再保存不可变原件；Agent永远看不到绝对路径。上传内容必须匹配文件扩展名，DOCX/PPTX还必须包含对应OOXML入口。Docling响应体、ZIP条目数、目录深度、单条目和总解压大小均有限额；转换结果只接受Markdown和通过图片魔数校验的受支持图片，并拒绝绝对路径、`..`、伪造扩展名、跨目录或远程图片引用。
- Grading multipart 上传只允许一个主报告和最多100个附件；每个文件最多10 MiB，附件合计最多50 MiB。主报告独立计入其10 MiB单文件上限，不占附件总额；解析附件时按文件流累计实际字节，超过附件总额立即拒绝并停止读取，不依赖请求头或文件读完后的校验。
- 作业名称识别只通过当前会话的受控文件工具读取转换后Markdown和原始文件基本名；`set_submission_title`由服务端绑定当前会话，Agent不能提交会话ID或路径。未成功调用该工具的命名轮次不得解锁自动批改。
- Docling地址仅允许环回HTTP，且不得包含凭据、query或fragment。DeepSeek身份识别只发送长度受限的原始文件基本名，不发送报告正文；完整正文仅由批改Agent通过当前会话工具按需读取。
- Docling不可达、超时、限流或5xx时，系统只持久化固定的安全错误码和教师说明，并保留不可变原件；不把底层socket错误、原始响应或可能包含敏感内容的解析错误返回页面。自动重试有次数上限，终态解析失败、安全拒绝或历史原件缺失不自动重试。
- Windows发布监督进程使用`Global\CourseAgent.Launcher.<workspace-sha256>`确保单实例，并原子维护受控runtime descriptor。复用实例前同时验证Workspace身份、owner token格式、监督进程存活、loopback URL与健康接口；API只返回版本、端口、backend和就绪状态，不返回PID、绝对路径或原始错误。监督进程只向经过验证且由其记录的子PID执行`taskkill /T /F`。
- 流式界面展示固定安全处理摘要和脱敏工具活动，不保存或展示Provider私有推理链、Prompt、密钥或跨会话正文。无视觉模型时，`read_submission_image`只返回`VISION_MODEL_NOT_CONFIGURED`文本码，不读取或返回图片字节、路径或底层错误；批改Agent必须将受影响项标记为证据不足或向教师确认。成功读取图片后的模型切换只发送非敏感模型ID与能力标签。
- API错误、普通日志和审计索引不得包含完整正文。
- Rubric API仅直接返回`RubricRequestError`中由程序定义的固定业务错误码与提示；未分类的`RubricServiceError`继续返回安全泛化错误，不回传来源名称、绝对路径或内部详情。模型执行预算和取消规则见[架构说明](architecture.md)。
- `POST /api/system/models/test`只临时验证连接而不保存；`PUT /api/system/models`验证后保存并要求重启。两者必须同时通过环回来源、精确Origin和CSRF Token检查；同源页面先从`GET /api/system/models`响应头取得本进程Token，跨源页面受浏览器同源策略限制不能读取。Provider错误只返回安全摘要。
- `GET /api/system/models`只返回非敏感端点元数据和`configured`状态，绝不回填密钥。关闭独立视觉Provider时，配置事务同时删除已不再使用的视觉凭据；任一步失败都会恢复旧配置与旧凭据。主模型未配置期间只开放静态页面、`/api/health`和模型设置API。
- 模型Provider远程地址必须使用HTTPS；HTTP仅允许`127.0.0.1`、`localhost`或`::1`，且地址不得包含用户名、密码、查询参数或片段。合法路径会保留；仅当显式完整地址以`/chat/completions`结尾时，程序选择Chat Completions协议并把该后缀从运行时Base URL移除，避免重复拼接。
- 模型配置保存由`Global\CourseAgent.ModelConfig.<workspace-sha256>` Windows内核Mutex串行化，可覆盖同一机器的不同登录Session；Mutex、Workspace内事务日志和Workspace外凭据目录使用同一个规范Workspace身份。独立helper持锁，父进程退出或管道关闭即释放，并由内核处理崩溃遗留所有权。helper若在临界区意外退出，主进程立即中止，由supervisor重启后按事务日志恢复，不能在失锁后继续写入。覆盖DPAPI密文前先原子写入`prepared`事务日志；日志只含旧非敏感配置及旧DPAPI密文/缺失标记。配置原子提交后日志标记为`committed`并清理；首次配置操作会恢复遗留`prepared`事务或清理遗留`committed`日志。启动时在同一锁内读取配置及主模型/视觉模型凭据快照，运行期持续使用该一致快照直至重启。
- 调试时如需内容片段，使用合成或脱敏数据并限制长度。

## 日志与审计

普通运行日志记录：

- 请求、session、batch和job的内部ID；
- 状态转换、耗时、重试次数和错误类型；
- release、Rubric、Prompt、提交和结果哈希；
- Provider请求ID（若可获得）。

普通日志不记录Prompt全文、学生正文、密钥、回调明文或完整模型响应。教师修改使用独立追加写审计事件，保存修改人、时间、前后哈希、结构化Patch和备注。

M2 的 SSE 响应同样视为安全边界：只发送回答文本、经验证引用与受限工具步骤，不能发送思维链、完整工具参数、资料原文、绝对路径或模型密钥。

## 公开网页读取

- 网络搜索默认走本机 DDGS helper，外部网页只能通过本会话的搜索结果 ID 读取，不能由模型提供任意 URL。
- 读取仅允许 HTTPS；解析域名和每次重定向都会拒绝环回、私网、链路本地和云元数据地址，IP literal 也执行相同检查。实际 HTTPS 连接固定到已校验的公有 IP，同时保留 URL 主机名用于 Host、SNI 和证书校验，不能在连接时再次解析目标域名。
- 仅处理 HTML/纯文本，整个抓取（包括 DNS 解析、重定向和读取响应体）共用 15 秒截止时间，并设置流式字节上限；超限或拒绝的响应会及时取消读取。非法 HTTP 状态和 205 响应会拒绝并关闭响应流。网页内容是不可信参考资料，不执行其中指令，也不写入普通日志或会话文件。

## 启动恢复

应用启动顺序：

1. 加载并校验非敏感配置；
2. 检查Workspace目录权限和路径边界；
3. 打开SQLite，启用外键并执行版本化迁移；
4. 校验active knowledge指针；
5. 协调正式结果文件与job状态；
6. 清理无引用临时文件；
7. 恢复未过期租约并重新排队可重试job；
8. 最后启动API、Channel和队列消费者。

恢复逻辑必须幂等，连续启动两次不能改变已经协调完成的状态。

M4启动时还会恢复`queued`、`running`以及未耗尽自动尝试次数的`waiting_for_converter`提交。若Docling Serve未运行，页面应显示“等待转换服务”而不是把文件判定为损坏；启动或恢复Docling后可由后台或教师手动重试。

## 备份与回滚

一致性备份至少包含：

- `workspace/knowledge/`；
- `workspace/assignments/`；
- `workspace/state/app.db`；
- 需要保留的非敏感配置。

备份前暂停领取新job并等待当前原子发布结束。知识库回滚通过切换`active.json`完成；批改结果不原地覆盖，教师修订通过审计事件和新结果哈希表达。

在实现自动删除前，正式结果和审计默认保留。任何批量删除功能必须先展示确定目标、要求确认，并使用可恢复方式或经过验证的备份。

单会话删除必须由教师在界面二次确认，服务端拒绝删除仍在转换、作业命名或批改的会话；数据库先以CAS写入删除墓碑阻止新任务准入，再使用已存的Assignment、batch和student内部ID清理受控目录，清理成功后删除会话行。清理失败保留墓碑以便安全重试。CSV下载按需生成、不落盘为事实来源；所有文本遵循RFC 4180转义，对以`= + - @`开头的字符串加前缀，避免电子表格公式注入。

## 企业微信

正式接入前必须完成目标组织内的连接验证，明确回调或长连接方式以及本机网络前提。适配器必须实现：

- 验签、解密和时间窗口检查；
- 消息幂等与短期去重；
- 快速确认和异步处理；
- 有上限的限流、超时和5xx重试；
- 用户、群和课程映射校验；
- 长消息安全拆分；
- 日志脱敏。

重复投递不得产生第二次Agent调用。未知用户、群或课程映射必须在调用模型前拒绝。

## 故障排查

| 现象 | 首先检查 |
|---|---|
|启动失败|Node ABI、配置Schema、Workspace权限、SQLite迁移|
|课程仍显示旧内容|`active.json`、release manifest和发布日志|
|job长期running|租约、worker日志、正式结果文件及resultHash|
|CSV缺行|终态JSON数量；重新运行单写者聚合，不手改CSV|
|重复批改|幂等键、唯一约束、启动协调顺序|
|企业微信重复回复|消息ID、去重保留期和异步重试记录|

故障处理不得直接修改SQLite状态或正式JSON。需要人工修复时先备份、记录原因，并通过受控维护命令执行。
