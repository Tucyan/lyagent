# Course Agent Windows 逐步图文使用说明

更新日期：2026-10-08。面向第一次使用的教师。先完成一份 Markdown 报告的流程，再尝试 PDF、Word 和批量作业。

本说明中的模型设置、课程资料、答疑、评分表、单份与批量批改截图均来自本机应用和真实 DeepSeek API；内容为专门编写的示例资料。本轮仅使用浏览器截图，解压、资源管理器和启动控制台位置保留文字说明。手册插图已全部重新拍摄为统一的1280×900；较长预览分段拍摄，不使用窄屏图或超长整页图。历史截图仍保留在验证报告中。详见[本轮验证记录](2026-10-08-real-interaction-report.md)。

## 1. 找到压缩包，准备解压位置

1. 将发布 ZIP 保存到本机磁盘。full 包包含文档转换依赖和模型，压缩包约 2 GB，展开约 3.81 GB；请预留额外空间保存课程资料和学生报告。
2. 保留发布方提供的外部 `SHA256SUMS.txt`，核对它与压缩包文件名一致。需要校验时，在 PowerShell 使用 `Get-FileHash -Algorithm SHA256 '压缩包完整路径'`，对照外部清单。
3. 本轮最终试用候选保存在仓库的 `release/trial-20261008-v4/`；取其中ZIP和匹配的外部清单。它复用历史full包的运行时、依赖和模型，更新当前应用构建，不是完整重建或正式发布。历史包仍保留，但不包含当前修复；不同包不能套用同一个哈希值。
4. 准备一个尚不存在的新目录，例如 `D:\CourseAgent\试用版`。不要解压覆盖原安装目录，也不要覆盖业务数据。
5. 使用 WinRAR 打开 ZIP，确认可以看到 `app`、`runtime`、full 包的 `models` 和 `start-course-agent.bat`。

> 截图留空：WinRAR 打开压缩包界面。本轮仅截取浏览器；请在 WinRAR 顶部工具栏找到“Extract To（解压到）”。

## 2. 在 WinRAR 中解压

1. 点击工具栏 **Extract To（解压到）**。
2. 在 **Destination path** 输入上一步准备的新目录，不要沿用已存在的默认解压目录。
3. 保留 **Ask before overwrite（覆盖前询问）**，不勾选 **Keep broken files（保留损坏文件）**。
4. 点击 **确定** 一次，等待进度窗口结束。文件较多，通常需数分钟；此前实测为 202.49 秒，本轮结果以验证报告为准。
5. 如果出现覆盖询问，先取消并换一个全新目录。如果报错或等待超过 7 分钟，请人工处理；不要启动仍在解压或解压失败的目录。

> 截图留空：WinRAR 解压设置。请在“Destination path（目标路径）”填写新目录，保留覆盖前询问，点击“确定”。

仅核对压缩包 SHA-256 与外部清单，不运行包内逐文件哈希、文件数量或清单扫描。哈希不一致时重新取得匹配的包与清单，不要改写预期哈希。WinRAR 报错或超时的目录不能用于试用；自动解压需记录退出码0，再通过实际启动验证。不要在 WinRAR 内直接运行启动文件。

> 截图留空：解压后的文件资源管理器。在解压目标目录中找到 `start-course-agent.bat`；下一步双击它。

## 3. 启动与停止

1. 在文件资源管理器打开完整解压目录。
2. 双击 **`start-course-agent.bat`**。正确文件名不是 `start.bat`，无需先安装系统 Node 或 Python。
3. 保持启动窗口运行。依次会提示准备模型、启动文档转换服务、启动应用网页；等待服务期间每约30秒说明已等待的时间。看到“应用已就绪”后，启动器会自动打开默认浏览器。
4. 使用启动器实际打开的地址。当前启动器从 `http://127.0.0.1:3001` 开始选择可用端口，不能固定假设为 3000。本次业务重拍使用发布候选的3001端口；首次设置示例使用独立空Workspace的3019端口。
5. 如果浏览器没有自动打开，先检查启动窗口是否仍在运行；不要反复双击启动文件。启动失败时记录窗口中提示，确认解压完整后再处理。
6. 结束使用前先等待任务完成，关闭启动窗口，再关闭页面。页面关闭本身不代表后台停止。

发布版默认将业务数据保存在 `%LOCALAPPDATA%\CourseAgent\workspace`。保留这个目录；解压目录与业务数据目录用途不同。本轮没有在既有业务目录写入测试数据。

> 截图留空：发布版启动控制台。本轮只拍浏览器，启动窗口应保持运行，勿反复双击。若迟迟未打开网页，保留窗口中的实际提示供排查。

第一次历史包启动验证在约两分钟观察上限内尚未进入就绪状态，已停止。用户重启电脑并明确要求继续后，第二次启动成功：约67秒后生成启动描述文件，随后健康检查通过，页面进入首次设置，并显示转换器就绪。耗时不是保证；尚未确认第一次等待较长的原因。

![首次设置界面：独立空Workspace，尚未保存模型配置，文档转换器已就绪](screenshots/2026-10-08-unified/00-first-setup.jpg)

如果要复现本次隔离验证，可自行在 PowerShell 执行以下命令，保留窗口等待。该目录没有模型配置，启动成功后应进入首次设置。若需停止，按 `Ctrl+C` 并等待退出。此命令仅适用于本机本次保留的解压目录。

## 4. 首次模型设置：DeepSeek

1. 第一次启动未配置模型时会进入 **首次设置**；已经配置后，可从工作台的 **模型设置** 进入同类表单。
2. 在 **模型供应商** 选择 **Qwen（Chat Completions）**。这里表示 Chat Completions 协议，本次实际使用的是 DeepSeek 服务。
3. 在 **模型 ID** 填写本账户可用的模型名称。本机配置并实测使用 `deepseek-v4-flash`；不要把示例名称当作所有账户都可用的保证。
4. **Base URL** 填写 `https://api.deepseek.com`。
5. **API Key** 输入自己的密钥。已配置后显示“已安全保存；留空表示保持不变”，不会回填原密钥。不要截图明文密钥或放入课程资料。
6. 首次试用纯文本报告可保持 **启用视觉模型** 不勾选。需要模型看图片时才单独配置支持图片的视觉模型。
7. 点击 **测试连接**，等待 **连接测试成功。**；失败时根据提示检查模型名、地址、密钥或网络。
8. 点击 **保存设置**，等待完成；发布监督模式会自动重启。首次设置完成后进入工作台；从已有“模型设置”保存时会重新加载本页，显示“设置已生效，应用已重启”，点击 **返回工作台并继续** 开展业务。

本轮通过应用安全配置服务在独立验收目录复用本机已有凭据，再实际点击“测试连接”和“保存设置”。未重新输入密钥。早期源码验收服务不处于发布监督模式；后续已在新发布候选中实际点击测试连接、保存并确认应用进程更换和健康就绪，模型设置页重新加载。

## 5. 创建课程

1. 进入 **课程资料库**。
2. 展开 **新建课程**。
3. 在“输入课程名称”填写名称，例如 **图文试用示例课程**。
4. 点击 **创建**，确认页面标题和“当前课程”都切换到新课程。

![展开新建课程并填写名称](screenshots/2026-10-08-unified/06-create-course-form.jpg)

## 6. 导入、检查并发布资料

1. 在本机准备一个 Markdown 资料目录，例如 `materials`，把课程要求保存为 `.md` 文件。本页导入的是 Markdown 目录；不要把 PDF 课件直接当作 Markdown 目录导入。
2. 在课程资料库确认“当前课程”正确，点击 **导入资料**，选择整个目录。
3. 等待“正在读取并整理资料…”结束。成功后进入 **修订草稿**，页面显示草稿版本与资料篇数。
4. 点击左侧资料名称，核对右侧 Markdown 源文及实时预览。修改内容后点击 **保存修改**，等待“已保存”。
5. 确认资料正确后点击 **发布并启用**。
6. 看到 **已发布并启用 v1** 和 **当前使用 v1** 即发布成功。之后修改资料，需创建修订并再次发布，答疑才能读取新版内容。

## 7. 提问并核对引用

1. 进入 **课程答疑**，选择刚发布资料的课程。
2. 点击 **＋ 新建对话** 可开始新对话；没有对话时也可直接输入首个问题。
3. 本次关闭 **联网搜索**，验证只依据课程资料回答。
4. 输入“实验报告需要哪些部分？满分是多少，各部分怎么分配？请依据课程资料回答。”，点击 **发送**。
5. 等待回答；生成期间可点击 **停止生成**。结束后可以继续追问。
6. 点击回答下方的引用按钮，核对原文与行号，而不是只看模型结论。

## 8. 创建评分表并让模型生成草稿

1. 进入 **评分量表**，点击 **＋ 新建评分表**。
2. 选择所属课程，填写 **会话名称**、**总分**，再填写 **作业要求** 或导入参考资料（两者至少提供一项）。
3. 本例总分 **10**，要求为“实验过程4分，结果分析4分，格式与总结2分；说明评分依据”。
4. 点击 **创建并选择评分制度**。
5. 选择合适制度。本例点击 **加分制** 下的 **选择并开始**，等待模型生成第一版草稿。
6. 核对右侧项目、最高分、评分方式与说明；聊天框可要求模型继续修改。

## 9. 人工修改与报错恢复

1. 点击 **人工编辑**，修改项目名称、最高分、评分方式和评分说明。
2. 点击 **保存人工修改**。
3. 如果提示“评分项目的分值上限之和必须等于评分表总分”，检查各项目最高分之和。例如 3＋4＋2＝9，不能保存为总分10的评分表。
4. 在当前编辑表单将第一项恢复为4，再点击 **保存人工修改**。不要关闭页面或反复点击冻结。
5. 成功后显示“人工修改已保存为草稿 v2”。

## 10. 校验并冻结

1. 点击 **校验并准备冻结**。
2. 有错误时先按提示修改；“建议补充评分锚点”属于建议，当前连续评分表仍允许冻结。正式使用前应检查标准是否足够清楚。
3. 校验通过后点击 **确认冻结为正式版本**。
4. 确认右侧显示 **冻结版本 v1** 和“评分表 v1 已冻结，可正式应用”。
5. 后续变更点击 **基于 v1 创建修订**；冻结版本不能直接修改。草稿和冻结版本分别编号，草稿v2冻结为正式v1是正常现象。

## 11. 上传一份报告并批改

本节分阶段展示独立示例：甲的新上传会话用于展示转换就绪，未开始评分；丁用于展示教师回答后生成3/10待复核草稿，未确认；第12节恢复甲原有5/10正式成绩展示导出。它们不是同一会话连续产生的分数。

1. 进入 **作业批改**，先选择冻结评分表。
2. 打开新建批改会话表单，确认“评分标准”显示正确名称及版本。
3. **学生姓名** 与 **学号** 要么同时填写，要么同时留空让系统识别。本例推荐填写“示例同学甲”和“20261008”。
4. **作业名称** 可填写“对照实验”，留空时模型会尝试识别正文与文件名。
5. 在 **学生报告** 选择 `20261008_示例同学甲_对照实验.md`。支持 Markdown、PDF、DOCX、PPTX、PNG、JPG、JPEG；旧 `.doc` 先转换为 `.docx`。
6. Markdown 引用图片时，在 **Markdown 图片目录** 选择对应的 `assets` 目录；没有图片时留空。
7. 首次试用建议不勾选 **转换完成后自动开始批改**，先核对转换结果与身份，再点击 **开始批改**。
8. 模型可能先询问评分尺度。阅读当前问题，点击对应选项；也可在输入框回答，点击 **回答并继续批改**。等待评分草稿生成；仍有必要信息缺失时继续回答具体问题。历史选项只供阅读，不再重复提交；只有当前待回答问题显示可操作选项。
9. 查看右侧逐项得分、分析依据与总分。**已有草稿** 或 **待复核** 都不是正式成绩。右侧内容较长时在该面板内向下滚动；左侧会话列表挤占空间时点击 **收起会话**。

## 11.1 Word 与 PDF：先检查转换，再开始评分

1. 在 **作业批改** 选择该报告对应的冻结评分表，点击 **新建会话**。
2. 同时填写学生姓名和学号，可手填作业名称；以原报告身份为准。
3. 点击 **学生报告**，选择 `.docx` 或 `.pdf`；首次验收先取消 **转换完成后自动开始批改**。PDF/Word 的内嵌图片由转换服务处理，不要为它们误选 Markdown 图片目录。
4. 点击 **创建会话** 一次，等待左侧对应会话显示 **转换完成 · 未开始批改**。若显示等待转换服务，保持启动窗口运行；失败时按该会话的明确提示重试。
5. 点击右侧 **学生作业**。对照原件检查标题、正文、表格数字和图片；有问题时在尚未锁定前使用 **编辑 Markdown** 修正，或换用完整原件重新上传。
6. 核对当前会话姓名、学号、作业名称。新建表单打开时，右侧显示“正在新建会话”，暂时禁用预览切换；完成创建后才显示新报告，避免误读上一会话的成绩。
7. 选对评分表并核对转换内容后，再点击 **开始批改**，按前面的教师问答、复核和确认步骤继续。需要模型判断图片时，先配置支持图片的视觉模型；图片能显示不等于文字模型已经看懂图片。

## 12. 复核、确认和单份导出

2. 出现 **需要教师复核并逐项确认** 时，逐项核对复核原因；需要改分时使用人工修订评分项。
3. 填写 **复核备注**，说明调整或接受评分的理由。
4. 点击 **确认并发布正式结果**，确认显示 **已确认** 后，再使用 **导出 JSON** 或 **导出 Markdown**。

## 13. 多份报告：批量上传与复核

2. 首次先选并发数 **1**，上传两份示例报告熟悉流程，再按模型服务限制调整。
3. 在 **学生报告** 多选文件；有图片时选择 **共享 assets 目录**。
4. 点击 **创建上传草稿**，检查每份文件状态。身份待补全时，同步填写姓名和学号，再按行内按钮提交；失败项按提示重试。

## 14. 遇到问题时下一步怎么做

| 页面现象 | 下一步 |
|---|---|
| 无法连接本地服务 | 检查启动窗口是否仍在运行；已退出则重新启动完整解压目录的 `start-course-agent.bat`，使用实际地址刷新。 |
| 模型认证失败 | 进入模型设置核对密钥，再测试连接；不要把密钥发到答疑窗口。 |
| 模型 ID 未找到 | 核对自己账户支持的模型名，修改后再测试连接。 |
| 答疑提示没有已发布资料 | 到同一课程的资料库发布草稿，再创建新对话。 |
| 评分表分值不一致 | 在人工编辑中检查各项最高分之和，修正后保存，再校验冻结。 |
| 只有草稿，上传时找不到评分表 | 回评分量表完成校验与冻结。 |
| 姓名与学号校验失败 | 两项同时填写；识别失败时人工补全。 |
| 等待转换服务 | 保留原件，确认发布版启动窗口仍在运行；服务恢复后重试转换，或先用 Markdown 验证文字流程。 |
| 待教师回答 | 打开对应会话，阅读具体问题并回答，再继续；不要只重启批次。 |
| 批次完成但仍有待复核 | 进入 Review 核对并正式确认。 |

本轮仅使用浏览器截图；WinRAR、文件资源管理器与启动控制台按当前要求留空并附说明。真实单份与批量批改、确认、下载已完成。相同正文仍可能得到不同模型分数，必须由教师复核；未配置视觉模型，不能据本次文字流程宣称图片识别已验证。其他验证进度以验证报告为准。
