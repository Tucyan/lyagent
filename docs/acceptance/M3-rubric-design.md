# M3 评分表设计验收记录

日期：2026-08-03

## 自动化验证范围

- 加分、减分、混合制Schema与确定性校验。
- 仅参考资料创建、无来源零模型推荐、评分制度持久化。
- 草稿乐观并发、冻结哈希、冻结崩溃恢复、历史版本与修订。
- Agent固定工具白名单、结构化问题/草稿、SSE安全摘要与完成轮次持久化。
- 重进会话不请求AI推荐，聊天记录、处理摘要和工具活动恢复。
- 教师可读预览与结构化人工编辑模型。
- Provider原始文本不会作为“思考摘要”转发或保存；页面只显示程序生成的处理阶段和安全工具摘要。
- 无模型配置时仍会创建可人工编辑的最小合法草稿，不会卡在制度选择之后。
- 可读预览与Markdown导出完整显示评分等级、证据、部分得分和重叠组语义；JSON仍是评分事实来源。
- 删除评分会话有二次确认，并会一并删除参考资料、聊天记录、当前草稿和全部冻结正式版本。

## 浏览器自主验收

在`/rubrics`使用当前配置的真实模型完成以下流程：

1. 以空作业要求和一份粘贴参考资料创建评分会话。
2. 选择减分制后不填写备注，直接生成第一版评分表。
3. 确认会话显示教师消息、折叠的模型处理摘要和本地化工具活动，预览不显示JSON。
4. 发送“现在的评分标准有进一步改进的建议吗”，确认Agent在会话中给出具体建议，并显示本轮未修改草稿；刷新前后的草稿版本和内容完全一致。
5. 在结构化编辑器中修改规则名称并保存，草稿版本递增且预览同步。
6. 打开并退出全屏预览，收起并展开左侧会话栏。
7. 校验草稿并二次确认冻结v1；确认仅冻结版本显示Markdown/JSON导出和“可正式应用”说明。
8. 用临时验收会话打开删除确认，核对删除范围文案；确认删除后会话从左侧列表消失且相关草稿和冻结文件均不可再访问。
9. 从冻结v1创建修订草稿，历史v1保持可选。
10. 让Agent跟进修改扣分值，确认草稿版本和预览更新。
11. 重新打开同一URL，确认减分制、聊天历史、工具摘要、草稿和冻结历史全部恢复，且页面明确显示不会自动调用AI。

页面包含可拖动的会话/预览分隔条，并以28%—72%的程序边界保持两侧可用。冻结版本不可直接编辑；必须从历史版本创建修订草稿。
