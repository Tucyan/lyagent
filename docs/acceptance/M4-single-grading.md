# M4 单份作业批改验收

## 范围

本里程碑提供`/grading`教师工作台：选择现有唯一课程所绑定的冻结评分表，上传一份学生报告，完成转换、会话式批改、教师Review、确认与JSON/Markdown导出。支持`.md`、`.pdf`、`.docx`、`.pptx`、`.png`、`.jpg`和`.jpeg`；旧式`.doc`返回415并提示转换。

## 启动准备

1. 将`config.example.json`复制为本地且被Git忽略的`workspace/config/app.json`，填写`deepseekApiKey`。
2. 按`mineru`配置在本机环回地址启动MinerU FastAPI；Markdown报告不需要MinerU。
3. 确认系统中只有一门课程，且已存在冻结评分表。现有评分表会绑定该唯一课程。
4. 运行`npm install`、`npm run build`和`npm start`，访问`http://127.0.0.1:3000/grading`。

## 建议验收步骤

1. 在“新建批改会话”中选择冻结评分表，上传`tests/fixtures/single-grading/ai-life-report/20260001_张晓明_生成式AI生活助手报告.md`。姓名和学号可完整填写；也可两项都留空验证仅从文件名识别。
2. 确认会话绑定学生张晓明、学号20260001，Markdown立即进入`ready`，原文可编辑且保存后版本递增。
3. 点击“开始批改”。确认中间栏按流式顺序穿插安全处理摘要、模型回复和工具调用；完成后处理过程与工具调用默认折叠。
4. 在右侧切换“学生作业/评分结果”，拖动分隔条并测试全屏。确认16条减分规则均有判断、理由、证据或证据不足标记及置信度。
5. 黄金样例只应触发`process_no_output`，程序总分为`85/100`。若真实模型产生偏差，请记录具体规则、理由和证据。
6. 使用“人工修订评分项”修改一个判断、分值、理由或置信度，填写修订备注并保存。确认总分与Review状态由程序重算。
7. 展开每个评分项的“查看证据”，核对行号、短引文或受控图片；对每条Review原因分别勾选确认，未全部勾选时不能发布。
8. 若存在Review原因，填写复核备注并确认全部警告；发布正式结果后确认只读，重复确认不会生成第二份结果。
9. 下载`export.json`与`export.md`，核对总分一致；确认原始学生文件哈希和内容未改变。
10. 分别上传同目录DOCX与PDF版本，通过真实MinerU检查转换标题、关键段落和表格。上传`.doc`文件应得到415和转换提示。
11. 批改运行中切换页面再返回，确认任务继续且事件按`runId`和序号恢复；只有显式停止按钮才取消运行。
12. 确认结果后下载JSON与Markdown；点击“创建结果修订”应进入新的未开始会话，原确认结果保持只读。锁定提交也可通过“创建提交修订”生成新会话。
13. 显式停止或模拟运行失败后，在原会话点击“重试批改”；若未配置模型，开启“转换完成后自动开始批改”必须在创建会话前返回503。

## 自动化证据

- `npm run check`：40个测试文件、189个测试通过，2个显式集成测试默认跳过。
- `RUN_REAL_AI=1 npm test -- --run tests/grading-real-provider.test.ts`：真实文件名识别与真实批改通过，16条规则完整提交，证据短引文均匹配锁定正文，程序重算85/100；最近一次耗时约155秒。
- PDF夹具已渲染为3页PNG逐页检查，无文字裁切、重叠或表格破损。DOCX的OOXML正文与表格结构通过自动检查；本机LibreOffice验收渲染启动异常，需在人工验收时用Word或可用的LibreOffice再次打开确认。

## 排除范围

- 多份并发、批次暂停/恢复、班级CSV汇总和自动发布正式成绩属于M5。
- 服务不安装或启动MinerU，不支持旧式二进制`.doc`。
- 不展示Provider私有思考链；界面只展示安全处理摘要与脱敏工具活动。
