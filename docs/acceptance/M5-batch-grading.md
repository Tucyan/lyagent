# M5 可恢复批量批改与班级汇总验收

## 交付范围

- 独立页面 `/grading/batches` 及管理栏入口，M4 `/grading` 保持单份会话优先。
- 一批 1–120 份作业，冻结同一 Assignment 与 Rubric，并发数可设为 1–8。
- 批次开始、暂停、恢复；单个 job 教师问答、最多三次尝试和失败后重试。
- SQLite 会话预留、租约 fencing 与启动协调；有效 JSON 结果或已持久化草稿不会重复调用模型。
- 每个 job/attempt 隔离的 JSON/Markdown 快照，以及从当前 attempt JSON 重建的 UTF-8 BOM 班级 CSV。
- 批次结束只进入待复核，不自动确认正式成绩。

## 启动方法

```powershell
npm install
npm run build
$env:PORT='3001'; npm start
```

打开 `http://127.0.0.1:3001/grading/batches`。

## 手工验收步骤

1. 在左侧进入“批量批改”，选择冻结评分标准。
2. 选择 1–120 份 Markdown、DOCX 或 PDF 报告，设置批次名称和并发数 4；页面等待所有异步转换完成后创建批次。
3. 启动后确认同时运行数不超过 4；点击暂停，等待正在运行的作业结束，确认没有新作业被领取。
4. 点击恢复，确认剩余作业继续；对等待教师的问题提交回答，对失败 job 执行重试。
5. 本轮结束后确认总数与各状态计数一致，且结果处于待复核而非自动确认。
6. 从作业名称进入 M4 复核并确认一份结果，再下载班级 CSV，确认最新分数、置信度和确认状态已刷新，且每个已生成快照的学生恰好一行。
7. 运行中重启服务，确认有效结果不会再次调用模型，过期租约可以继续处理。

## Windows Release 回归验收（2026-08-10）

1. 使用一份非法身份文件、一份引用共享图片的 Markdown 和 10 份仅文件名不同的 Markdown 创建上传草稿；逐项确认身份、转换、命名和错误状态。
2. 主动制造一个缺图或转换失败项，刷新页面并重启服务；成功项必须保留，失败项可补填身份、替换文件或单独重试，不得重新上传全批次。
3. 共享 `assets/` 中同一图片可被多份报告引用，但每个隔离提交目录只包含该报告实际引用的图片；某份报告缺图只失败该项。
4. 草稿保留项全部 `ready` 前提交返回 `BATCH_UPLOAD_NOT_READY`；全部就绪后一次事务创建正式批次并预留会话，重复提交返回同一批次。
5. 取消草稿会清理未产生会话的 staging；已经创建的单份会话保留并在响应中列出。
6. 继续完成并发批改、Review 和 CSV 导出；批次允许 1–120 份，同名作业会话允许存在，但同一批次重复会话或重复学号必须拒绝。

- 120 份确定性合成报告：恰好生成 120 个 JSON、120 个 Markdown、120 行 CSV 数据，模型替身调用恰好 120 次，并发峰值为 4。

- 崩溃注入覆盖模型返回后、结果 rename 后和 SQLite 终态提交前；恢复后已有有效结果的额外模型调用为 0。
- 真实前端交互上传 30 份合成 Markdown：观察到 4 个运行中 job；暂停稳定后为 12 个待复核、18 个等待中、0 个运行中；恢复后为 30/30 待复核，并成功触发 CSV 下载。
- 页面最终复核时文档宽度与视口宽度同为 1265 像素，无整页横向溢出；明细表在卡片内部滚动。

- 上述并发验收使用确定性 grader，以保证状态和调用次数可重复。没有调用真实 DeepSeek API；本里程碑不需要以真实模型消耗替代并发、恢复和幂等验证。
