# 计算机网络评分 Agent 实测
本地新建课程「计算机网络」。由配置中的真实评分设计 Agent 生成三份量表，保留首轮生成版本并冻结为 v1，再用真实批改 Agent 测试六份虚构 Markdown。人工预期在运行前确定，批改只产生测试草稿。

| 作业 | 评分制度 | 完整样例（预期 → 实测） | 边界样例（预期 → 实测） |
|---|---|---|---|
| [IPv4 子网划分](subnet-作业.md) · [量表](subnet-评分标准.md) | 加分制 | [CN101](CN101.md) 20 → 20 | [CN102](CN102.md) 19 → 19 |
| [TCP 累计确认](tcp-作业.md) · [量表](tcp-评分标准.md) | 减分制 | [CN201](CN201.md) 20 → 20 | [CN202](CN202.md) 14 → 14 |
| [DNS 递归解析与缓存](dns-作业.md) · [量表](dns-评分标准.md) | 混合制 | [CN301](CN301.md) 20 → 0 | [CN302](CN302.md) 19 → 5 |

- IPv4 仅在错误广播地址所属子网扣 1 分。该次实测符合预期，但生成量表把固定 4 分写成 4–4.99 分，仍有漂移空间。
- TCP 错填第二个 ACK 时仅扣 6 分。样例已解释下一期待字节，未因该数值笔误再次扣机制分。
- DNS 量表增加了在答案中重述域名和无缓存前提、解释 TTL 递减及说明两种错误的处理方式等额外要求。边界样例只区分含义就应得奖励，实际未得。两份样例的基础答案逐字相同，解析路径仍分别得 0 和 8 分。将 DNS 说成 HTTP 的 3 分固定扣分正确触发，但无法抵消量表和判分偏差。
- 总体有 4/6 个样例与预设分数一致。本次只验证这六份。建议正式使用 DNS 修订版前，先去掉额外要求，明确题设不必复述，再用相同基础段落复测基础得分是否一致。
