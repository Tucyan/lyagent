# Course Agent Development Environment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Initialize a runnable Windows TypeScript project for the course-assistant MVP described in `plan.md`.

**Architecture:** Keep the application as one TypeScript project with a small core layer: a path-confined Workspace, typed MessageBus, ToolRegistry, AgentRouter, and Pi-backed AgentRuntime. Create the workspace layout and configuration needed by later MVP stages, while keeping agent-specific and service directories ready for incremental implementation.

**Tech Stack:** Node.js 24, npm, TypeScript, tsx, Vitest, Zod, Pino, p-queue, unified/remark, fast-glob, better-sqlite3, Fastify, and `@earendil-works/pi-agent-core`/`@earendil-works/pi-ai`.

- [x] **Step 1: Add package metadata and scripts**

  Define `dev`, `build`, `start`, `test`, `test:watch`, `typecheck`, and `check` scripts. Pin runtime dependencies and use the published Pi SDK packages at the version represented by the supplied source archive.

- [x] **Step 2: Add strict TypeScript and Vitest configuration**

  Use ESM, `NodeNext` module resolution, strict checking, `src` as the source root, and `tests` as the test root.

- [x] **Step 3: Create the plan-defined Workspace directories and safe defaults**

  Create `workspace/config`, `workspace/inbox/materials`, `workspace/knowledge`, `workspace/assignments`, `workspace/sessions/wecom`, `workspace/sessions/web`, `workspace/state`, and `workspace/logs`; copy `config.example.json` to `workspace/config/app.json` only when the latter does not exist.

### Task 2: Implement the phase-1 core boundaries

**Files:**
- Create: `src/core/workspace.ts`
- Create: `src/core/message-bus.ts`
- Create: `src/core/tool-registry.ts`
- Create: `src/core/agent-router.ts`
- Create: `src/core/agent-runtime.ts`
- Create: `src/main.ts`
- Create: `src/schemas/messages.ts`
- Create: `src/schemas/tools.ts`

- [x] **Step 1: Add tests for path confinement, tool registration, message delivery, and route selection**

  Verify traversal outside the workspace is rejected, registered tools execute only through the registry, messages are delivered to subscribers, and the four plan-defined agent keys route deterministically.

- [x] **Step 2: Implement the minimal typed core**

  Make `Workspace.resolve()` reject absolute paths and `..` escapes; make `ToolRegistry` expose only registered tool names; make `MessageBus` support typed subscription and publish; make `AgentRouter` map channel/page intents to agent keys.

- [x] **Step 3: Wrap Pi Agent behind `AgentRuntime`**

  Accept an injected Pi-compatible runner so tests do not require model credentials, and expose a `run()` method that records the selected agent key and prompt.

### Task 3: Install dependencies and verify the environment

**Files:**
- Modify: `package-lock.json` (generated by npm)

- [x] **Step 1: Extract the supplied Pi SDK source into `vendor/pi-main`**

  Do not alter `pi-main.zip`; use the extracted package as the local SDK source.

- [x] **Step 2: Install application and SDK dependencies**

  Run `npm install` in the app root. Use the published Pi packages because the supplied source archive omits generated model data and regenerating it requires an unavailable `models.dev` connection.

- [x] **Step 3: Run typecheck, tests, and the CLI smoke start**

  Run `npm run typecheck`, `npm test -- --run`, and `npm run start`; confirm the CLI prints the configured workspace path and exits successfully.

## Self-review

- The plan covers the phase-1 initialization items from `plan.md`: TypeScript project, Pi SDK dependency, runtime boundary, tool registry, workspace path restriction, message bus, router, and a runnable logging/startup surface.
- Later agent, service, database, channel, and React features remain as empty directories because they are subsequent phases in `plan.md`.
- No production model call is required during initialization; credentials are intentionally not committed.
