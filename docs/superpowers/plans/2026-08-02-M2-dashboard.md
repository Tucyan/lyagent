# M2 Dashboard 实施计划

## 目标

将教师/管理员工作台设为根路由 `/`，把现有课程资料库迁移到 `/knowledge`，保留 `/qa` 课程答疑。工作台仅展示 M1/M2 已实现能力的真实聚合数据，不新增遥测或调用模型。

## 范围

- 新增 `GET /api/dashboard` 聚合接口：课程、已发布课程、有效文档、答疑会话、课程状态和最近活动。
- 新增 Dashboard 与管理端左侧导航；未实现的后续模块仅作为禁用入口。
- 为课程资料库保留 `/knowledge`，答疑保留 `/qa`。
- 支持手动刷新、空状态、课程资料库和答疑的上下文跳转。
- 不实现 Rubric、批改、批量任务、系统运维或企业微信功能；不展示占位统计。

## 实施顺序

1. 先增加 Dashboard API 失败测试，覆盖空工作区、多课程隔离、发布时间线、损坏发布状态和敏感信息边界。
2. 实现只读 `DashboardService` 与 `GET /api/dashboard`，复用受控的课程、知识与会话服务。
3. 为 `/knowledge` 静态入口增加回归测试并注册 SPA 路由。
4. 提取课程资料库页面，新增 Dashboard 与响应式管理端导航。
5. 更新架构、开发与测试文档；执行 `npm run check`、`npm run build`，并进行本地浏览器验收。

## 验收标准

- 根路由展示真实 Dashboard；`/knowledge` 和 `/qa` 可直接访问。
- Dashboard 不读取 staging、不暴露正文、绝对路径或密钥，且不调用模型。
- KPI、课程状态、最近活动来自当前 Workspace 的真实数据；最近活动最多八条并按时间倒序。
- 损坏的单个 active release 在 Dashboard 中显示为不可用，不影响其他课程。
- 窄屏可打开和关闭管理端导航；尚未实现的模块不可点击。
