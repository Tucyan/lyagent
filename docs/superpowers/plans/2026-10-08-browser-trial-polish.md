## 真实API实际遇到的体验问题

| 实际现象 | 对用户的影响 | 当前状态/进一步目标 |
|---|---|---|
| 点击教师回答选项后模型只解释，仍无评分草稿 | 用户以为已经回答，却不知道怎么继续 | 已改回答语义与按钮文字，真实API回归成功；保留现有修复 |
| 选项被挤成竖条，导出和修订按钮异常换行 | 难以阅读、定位和操作 | 已在1280、1024、390宽度验证并补拍32–34；操作按钮正常尺寸、无页面横向溢出 |
| 评分项显示experimental_process等内部标识 | 教师不易对应评分表中的中文项目 | 已按会话绑定的冻结评分表显示中文名称；内部ID与评分事实不变 |
| 普通咨询尝试教师提问工具失败，页面只提示保留内容重试/重启 | 没说明失败原因或应该改用哪个操作 | 已分类为当前阶段操作不可用，提示先开始批改或查看已有草稿；失败测试和回归通过 |
| 相同正文的乙、丙分别得到6/10和5/10 | 教师需额外复核一致性，对自动评分信任受影响 | 待明确/复用评分尺度并做独立复核；不能宣称已解决模型波动 |
| Markdown报告仍出现转换完整性复核要求 | 用户可能不理解文字报告为何要复核表格和图片 | 已定位为所有评分注意事项共用历史代码；保留复核要求，显示具体说明，不误称转换问题 |
| 成绩已确认后，批次仍写“本轮已结束”，Review恢复后复核框未勾选 | 任务完成与成绩正式确认容易混淆 | 成员显示成绩已确认，复核页只读恢复，隐藏重复确认与直接改分控件；截图35–36 |
| 发布包启动等待时没有可见进度，首次观察上限内未就绪 | 用户容易以为卡住并重复启动 | 已增加阶段与约30秒等待提示，v3实际输出通过；未断言首次较慢的根因已解决 |
| 模型生成的选项包含evidenceInsufficient=true等技术字样 | 对用户暴露实现术语，降低可理解性 | 已添加表达约束，真实DeepSeek教师问答回归通过，截图37–38；历史消息保持原样 |

这些是实际交互观察，不是推测漏洞。首次发布成功时的浏览器控制调用超时属于控制工具问题，不列为应用失败。新源码发布候选、PDF/DOCX转换及设置重启后续已验证；视觉模型仍未配置实际验收，不归为已证实的产品故障。
