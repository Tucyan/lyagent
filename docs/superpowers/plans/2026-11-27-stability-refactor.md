# 稳定性与可维护性优化实施计划

> **For agentic workers:** Use the subagent-driven-development workflow. Each behavior change starts with a failing test and ends with independent review.

目标是在现有里程碑内降低数据丢失、恢复失败和日常维护成本。教师端与学生端继续通过受控 Workspace 和 SQLite 管理状态。实施基线为 27f4fe2，学生端采用同一 Workspace 单实例部署。验收范围以[里程碑总表](2026-08-02-course-agent-milestones.md)为准。

## 1. 数据一致性

- [x] 阻止删除已被单份会话、批次或上传草稿引用的评分表。覆盖导入或新建引用与删除的竞争、冲突响应及正常删除。
- [x] 在学生端暂存区验证课程资料包，验证通过后安装不可变目录并原子切换 active 指针。覆盖损坏内容、同版本冲突和安装后的重试。
- [x] 分离正式成绩的查询与恢复。正常查询不修改成绩文件、审计和 SQLite 时间，缺失派生产物继续由有效 JSON 补齐。

## 2. 学生端与答疑恢复

- [x] 在业务数据库打开前取得同 Workspace 跨进程锁。验证重复启动保护在途额度，以及进程退出后恢复预占。
- [x] 在学生端 SSE 响应断开时取消模型调用，在未提交答案时退额。统一两个前端的分帧及终态识别，验证缺少终态与已提交后丢失响应。
- [x] 列表隔离单个损坏会话，返回其余会话及脱敏计数，整体读取失败保留为错误。

## 3. 运行与发布验证

- [x] 公开独立的任务恢复状态，记录安全错误码，验证恢复失败和有界退出。
- [x] 添加 Windows 与 Linux 验证工作流，使用发布清单锁定的 Node 版本。
- [ ] 记录远端干净环境的 CI 结果。Windows 检查教师端，Linux 检查学生端。
- [x] 随行为变更更新长期文档，将被替代的历史记录移入[归档](../../archive/README.md)。

## 4. 按职责拆分

- [x] 从批改会话服务提取数据库迁移，再提取提交版本与文件管理。覆盖旧库、并发准入及结果恢复。
- [x] 合并首批导航、评分表和批改样式声明。浏览器覆盖两个门户、三档宽度和展开/折叠侧栏。
- [ ] 继续整理剩余页面级 CSS，以计算样式和关键交互回归验证层叠顺序。

每批使用合成数据，执行 npm run check 和 npm run build。发布包验收遵循 AGENTS.md 的压缩包和实际启动规则。
